## 已确认的还原缺口：人物着色器

`Material/Character.mat:11` 引用 `Shader/Shader Graphs_CharacterShader.shader`，文件虽存在，但第 22 行有 `//DummyShaderTextExporter`。其 fragment 函数只返回 `float4(1.0, 1.0, 1.0, 1.0)`，没有采样人物贴图，没有实现原来的肤色、服装颜色、法线及 SSS 光照处理。文件里的 Properties 仅保留参数接口，不代表实现已恢复。

因此，人物模型、材质和基础贴图的序列化链条已恢复；**当前人物外观不能与原版一致**。这是确认存在的实现缺口，不是缺失 GUID。不能用“所有引用存在”推断画面已经正确。建议保留原 dummy shader 作为证据，在另一个可运行修复工程中根据原版渲染或编译 shader 证据重建；直接填入猜测 shader 只能称为替代实现。

## 动画范围与后续验证

三个入口均未包含 Animator（class 95），不能由此认定人物动画丢失。`PlayerBody.cs:149–155`、`PlayerHands.cs:327` 等反编译代码直接插值身体/手部位置和旋转，属于代码驱动运动。`DeadPlayer.prefab:4752` 的旧 Animation 组件引用 `AnimationClip/DeadPlayerSlap.anim`，该 GUID 及动画 YAML 的 fileID 已在闭包中解析。当前未验证动画播放、骨骼方向、换装、NPC 外观或相机视角。

“与原版一样”仍需 Unity 导入/编译成功，再逐场景比较角色外观、装备与动作；这次静态核对不能替代运行验证，也不能还原开发者原始 DCC 文件或构建时未包含的资源。
