# 人物配色及遮罩修复证据

CharacterShader 原版来自 `original-artifacts/How to Fish_Data/sharedassets0.assets`，Shader pathID 490，原始对象 SHA-256 `6762e2667b6d36c511c7f93c7fea210679f8c4b1972805854d54007bb38d4a93`。`Tools/Inspect-CharacterShader.py` 解压编译 blob 并调用 Windows D3DDisassemble，输出 84 个原版程序反汇编和序列化属性到 `CompilationChecks/character-shader-evidence`。

program-10 的像素程序清楚保留配色选择逻辑：UV 通道 2 的 x 分量在四个区间 0.15–0.25、0.35–0.45、0.55–0.65、0.75–0.85 时，分别选择 Skin、Primary、Second、Third 参数；每个参数的 z 分量 >= 0.5 才覆盖原 UV 通道 0 的 palette 坐标，覆盖坐标取参数 xy，再从 Colors 贴图取样。输入/输出寄存器对应关系可在 program-1 的 vertex TEXCOORD0–3 传递中复核。这些向量不是 RGB。ColorPicker.cs 同样把 32×32 色板格子的 UV 和启用标志 1 传给 LocalSkin，ShaderManager.cs 原样写入四个 shader 属性。

本轮在既有近似 CharacterShader 中按上述证据恢复 palette 选择逻辑；原来的近似光照仍保留，尚未完整重建原版阴影、SSS 和法线算法，不能称为原版完整着色器等价恢复。

Custom/DepthMaskShader 来自同一 assets，pathID 525，SHA-256 `4b9e118c80b43fa6b4ae5c54281f672d4589d2fa13503ac1660c70f4487332ca`。序列化状态保存为 `CompilationChecks/depth-mask-original-state.json`，证据为 ColorMask 0、ZWrite Off、ZTest LEqual、Cull Back，Stencil Ref/ReadMask/WriteMask 64、Comp Always、Pass Replace，原始 Queue 为 Geometry-1。材质 DepthMask 的覆盖队列为 2002，继续保留。它写 stencil 位 64，不写颜色或深度；已修复导出占位 shader 恒白且无 stencil 的错误。

Unity 验收入口 `RecoveryVisualBehaviorValidation.Run` 不保存场景或材质变更，检查 VFX 事件在世界位置的发射、连续 burst 并存及 shader 编译状态，再在 GPU 上分别修改四个 palette 参数并读取实际像素差异。输出 `CompilationChecks/visual-behavior-validation.json`。该工具需由主任务在独立验证副本中运行；本轮子任务未启动 Unity，未宣称实际运行通过。
